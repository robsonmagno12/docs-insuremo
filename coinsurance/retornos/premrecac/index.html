🔄 Lógica de Negócio

1. Mapeamento de TipoMov

⚠️ Atenção: A lógica de campo PR_COSS_AC varia de acordo com o TipoMov.
TipoMov Origem Campo PR_COSS_AC Descrição
101 PolicyCore PrCossAc Emissão original da apólice
102 OldPolicy (Gateway) PrCossAc Apólice anterior do endosso
105 NewPolicy (Gateway) PrCosCed ⚠️ Nova apólice do endosso (cedido)

2. Processamento de Endorsements

Fluxo:

  1. Busca EndoNo por PolicyNo no IndexService
  2. Se não encontrar: processa como emissão original (TipoMov 101)
  3. Se encontrar: carrega dados históricos via Gateway
  4. Processa OldPolicy se BaseDate coincidir (TipoMov 102)
  5. Processa NewPolicy se BaseDate coincidir (TipoMov 105)
// 1. Busca EndoNo por PolicyNo
String endoNo = findEndoNoByPolicyNo(policyNo)

if (endoNo) {
    // 2. Carrega dados históricos via Gateway
    Map endorsementData = loadEndorsementByEndoNo(endoNo)
    
    // 3. Processa OldPolicy (TipoMov 102)
    if (endorsementData.OldPolicy && endorsementData.OldPolicy.BaseDate == baseDateIndex) {
        processPolicy(endorsementData.OldPolicy) // usa PrCossAc
    }
    
    // 4. Processa NewPolicy (TipoMov 105)
    if (endorsementData.NewPolicy && endorsementData.NewPolicy.BaseDate == baseDateIndex) {
        processPolicy(endorsementData.NewPolicy) // usa PrCosCed
    }
} else {
    // 5. Sem endorsement: processa como emissão original
    processPolicy(policyCore) // TipoMov 101, usa PrCossAc
}

3. Agregação de Valores por Ramo

ℹ️ Importante: O PREMAC gera uma linha por ramo, agregando valores de todas as coberturas daquele ramo. 
// Agrupa por CodRamo
Map<String, Map<String, BigDecimal>> ramoTotals = [:]

// Para cada Coverage
coverages.each { cov ->
    String codRamo = cov.CodRamo
    
    // Inicializa se não existir
    if (!ramoTotals[codRamo]) {
        ramoTotals[codRamo] = [
            PrCossAc: 0.00,
            ComCossAc: 0.00,
            PrEmit: 0.00,
            Cofee: 0.00,
            AdFrac: 0.00,
            ProLab: 0.00
        ]
    }
    
    // Soma valores por ramo
    ramoTotals[codRamo].PrCossAc += (tipoMov == 105) 
        ? cov.PrCosCed 
        : cov.PrCossAc
    
    ramoTotals[codRamo].ComCossAc += cov.ComisCoss
    ramoTotals[codRamo].PrEmit += cov.OverrideBeforeVatPremium
    ramoTotals[codRamo].Cofee += cov.Cofee
    ramoTotals[codRamo].AdFrac += cov.AdFracCoss
    ramoTotals[codRamo].ProLab += cov.LaborAmountCoss
}

// Gera uma linha por ramo
ramoTotals.each { codRamo, totals ->
    generateCsvLine(codRamo, totals)
}

🔍 Troubleshooting

Erro: "CoInsuranceInfoList vazio"

Causa: Apólice sem informação de cosseguro

Solução: Verificar se a apólice tem CodCoss=05908

Erro: "Gateway não retornou dados"

Causa: Endorsement não encontrado ou erro no Gateway

Solução: Verificar se EndoNo está correto no IndexService

Erro: "PolicyId ausente"

Causa: Documento do Index sem entity_id ou PolicyId

Solução: Verificar estrutura do documento retornado pelo Index

🔄 Lógica de Negócio - Estratégia Dual Module

⚠️ Estratégia: SINAVAC combina dados de ClaimCase (dados base do sinistro) com ARAP (histórico de transações financeiras).

Fluxo de Processamento

  1. Query ClaimCase Index por BaseDate
  2. Load ClaimCase Data completo
  3. Extract ClaimNo do ClaimCase
  4. Query ARAP por ClaimNo (com paginação)
  5. Se ARAP encontrado: Para cada Transaction, gera linha combinando ClaimCase + ARAP
  6. Se ARAP não encontrado: Gera linha com dados do ClaimCase apenas (fallback)

Código de Implementação

// 1. Busca ClaimCase
List<Map> claimDocs = fetchClaimsCaseBatch(baseDate, cursorId)

claimDocs.each { claimDoc ->
    String claimNo = claimDoc.ExtClaimNo
    
    // 2. Busca TODOS os ARAP para este ClaimNo
    List<Map> arapHistorico = fetchAllArapDataByClaimNo(claimNo)
    
    if (arapHistorico.isEmpty()) {
        // Fallback: usa dados do ClaimCase
        detailedLogger.log("  Sem ARAP - usando dados do ClaimCase")
        generateLine(
            claimCase: claimDoc,
            arap: null
        )
    } else {
        // Para cada ARAP Transaction, gera uma linha
        detailedLogger.log("  ${arapHistorico.size()} transacoes ARAP encontradas")
        arapHistorico.each { arapData ->
            generateLine(
                claimCase: claimDoc,  // Campos base
                arap: arapData         // TipoMov e VrMov
            )
        }
    }
}

Paginação do ARAP

List fetchAllArapDataByClaimNo(String claimNo) {
    List allArapData = []
    int pageNo = 1
    boolean hasMorePages = true
    
    while (hasMorePages) {
        // Query ARAP com BizTransType=CLAIM
        PagedResultArap response = bcpSdkClient.arapApi()
            .newAdvanceQueryArapRequestBuilder()
            .searchConditionRequest([
                conditions: [
                    ClaimNo: claimNo,
                    BizTransType: "CLAIM"
                ],
                pageNo: pageNo,
                pageSize: 100
            ])
            .doRequest()
            .getBody()
        
        if (response.totalElements > 0) {
            response.elementsInCurrentPage.each { arap ->
                // Extrai Transaction de cada ARAP
                Map transaction = arap.Transaction
                allArapData.add(transaction)
            }
            
            hasMorePages = (response.elementsInCurrentPage.size() == 100)
            pageNo++
        } else {
            hasMorePages = false
        }
    }
    
    return allArapData
}

🔄 Lógica de Negócio - Cálculo de Valores

⚠️ Cálculo Especial: SINPENDAC possui um cálculo único para o campo VR_TOT, aplicando 40% sobre o valor total do movimento.

Fórmulas de Cálculo

VR_PENDENTE = ExtCededCoinsuranceAmount
VR_TOT = ExtMovementAmount × 0.40

Implementação

// VR_PENDENTE: valor cedido ao cosseguro
BigDecimal vrPendente = claimDoc.ExtCededCoinsuranceAmount ?: 0.00

// VR_TOT: 40% do movimento total
BigDecimal movementAmount = claimDoc.ExtMovementAmount ?: 0.00
BigDecimal vrTot = movementAmount * 0.40

generateLine(
    vrPendente: vrPendente,
    vrTot: vrTot,
    // ... outros campos
)

💡 O que é IBNR?

Incurred But Not Reported (IBNR)

Definição: Reserva técnica para sinistros que já ocorreram mas ainda não foram reportados à seguradora.

Componentes do SINPENDAC:

  • VR_PENDENTE: Valor conhecido e provisionado
  • VR_TOT: Estimativa total incluindo IBNR (40% rule)
